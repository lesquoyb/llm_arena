New calibration

Compare initial prompts against fixed opponents. Each candidate starts with a fresh conversation; only training results return to the target.

Provider configuration

Saved participants are shared with the competition application. Edit the JSON here for an unsaved model. API keys can also come from the named environment variables. Ollama uses the OpenAI compatible protocol and an HTTP loopback endpoint.

Reference documents

Edit the learning material supplied through read_docs. Changes apply only to this candidate; engine catalogs and evaluation rules remain fixed. The automatic analyst can edit these documents too.

Tools available to the target

These are the registered Arena MCP tools. Disabled tools are rejected by the dispatcher, even if the model guesses their names. Earlier training fights are the only competition records accessible to the target.

Panels, scenario and optimizer settings

Training drives improvement and plateau detection. Validation compares prompts. A separate audit panel evaluates the selected candidate after search. All panels use both starting sides. Model outputs may vary even with a seed.

Search settings

Utility = validation score − round penalty × convergence round − token penalty × mean tokens / 1,000,000. A candidate must improve utility and stay within score tolerance in every paired replicate. Parameter grid replaces analyst editing with a deterministic Cartesian sweep.

No token or call limits apply by default. Remote API calls require allow_paid_calls=true. If set, max_total_usd covers the entire study, including the analyst.
