1 · Configure a study Models, learning material and limits

New calibration

Each candidate tests one system prompt and its reference documents. Rounds improve the script under that same prompt. In automatic mode, the analyst revises the learning material between candidates.

Provider configuration

Saved participants are shared with the competition application. Edit the JSON here for an unsaved model. API keys can also come from the named environment variables. Ollama uses the OpenAI compatible protocol and an HTTP loopback endpoint.

Reference documents

Edit the learning material supplied through read_docs. Changes apply only to this candidate; engine catalogs and evaluation rules remain fixed. The automatic analyst can edit these documents too.

Tools available to the target

These are the registered Arena MCP tools. Disabled tools are rejected by the dispatcher, even if the model guesses their names. Earlier training fights are the only competition records accessible to the target.

One observation per prompt candidate

Repetitions start from scratch. Within each repetition, rounds improve the same script using earlier results. The prompt changes only between candidates.

Panels, scenario and optimizer settings

Training drives improvement and plateau detection. Validation compares prompts. A separate audit panel evaluates the selected candidate after search. All panels use both starting sides. Model outputs may vary even with a seed.

Independent Laya diagnostics

Laya diagnoses task understanding, language/API problems, tools, use of results and progress. Its probability distributions are saved for you, never sent to the analyst and never used to select candidates. Missing reasoning or an unavailable Laya installation does not block optimization.

Exploration and exploitation

The analyst independently chooses all changes. Exploitation starts from the best candidate; exploration may revisit another valid archived candidate to try a different hypothesis. Combat results and configured penalties decide whether to keep the result. Leave the candidate limit blank and disable plateau stopping to continue until manually stopped.

Analyst proposal check

Checks for supplied combat solutions and prescribed tactical recipes. Ambiguous proposals are not approved. This uses the selected local Laya checkpoint. It can make mistakes; it is disabled by default.

Objective settings

Utility combines evaluation score, the optional Laya weight and the round/token penalties. Combat scoring protects every paired replicate within the score tolerance. In hybrid mode, Laya only breaks equivalent combat scores. Parameter grid replaces analyst editing with a deterministic Cartesian sweep.

Preparation budget per round

The target sees these limits and the remaining budget in tool results. Empty fields mean unlimited. Saved files are frozen when a limit is exhausted.

Other limits and budget JSON

Quick diagnosis starts with a short call/tool budget. Clear limits for unlimited preparation. Remote API calls require allow_paid_calls=true. If set, max_total_usd covers the entire study, including the analyst.
