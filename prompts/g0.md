## Execution and API contract
LeekScript is not JavaScript. The engine executes the entrypoint's top-level statements once per entity turn. Defining a function does not call it. There is no implicit main() or nextTurn() callback; call your own helpers explicitly. Reaching the end of the file ends the turn.

These are actual global API calls, not pseudocode:
- getNearestEnemy() returns a runtime entity ID, or -1 if absent.
- isAlive(entity_id) returns a boolean.
- getEntity() returns your runtime entity ID. getLeekID() is a different persistent ID.
- getWeapons() returns an array of equipped weapon IDs, not weapon objects. No getWeaponId conversion is needed.
- setWeapon(weapon_id) selects an equipped weapon.
- getWeaponCost(weapon_id) returns its TP cost; getWeaponCost() uses the selected weapon.
- useWeapon(entity_id) attempts an attack with the selected weapon and returns an integer action result; compare with USE_SUCCESS. It does not accept a weapon ID as an additional argument.
- moveToward(entity_id) and moveToward(entity_id, mp_to_use) perform movement and return movement performed.
- getTP() and getMP() return remaining resources.

Runtime entity IDs are opaque handles, not positions or distances. Never derive range, coordinates, health or turn order by doing arithmetic on an entity ID or comparing its numeric magnitude. Entity IDs, cell IDs and equipment IDs are distinct even though all are integers. To reason about position, obtain cells with getCell(entity_id) and consult verified cell/distance/targeting APIs; do not substitute an entity ID where a cell is required. Geometric distance alone does not establish line of sight or attack legality.

Arrays use count(array), not array.length. Declare locals with var; named functions use function name(arguments) { ... }. Game functions are global with no imports or external libraries. Names such as fireWeapon, moveTo, allEnemiesDead and finishTurn are not substitutes for documented calls. A lookup with zero matches is evidence not to use that name, not permission to guess its signature. Use compiler diagnostics rather than speculative API searches to diagnose saved code.

## Documentation tools: use the correct namespace
read_file reads only your own workspace source files. Shared documentation is not in that workspace. Use read_docs for authoring.md, corpus/ paths and leekscript-v1/ paths. For example: read_docs({"path":"corpus/language/cheatsheet.md"}). A read_file 'No such file' error for one of these paths does NOT mean the documentation is missing.
lookup_api accepts query for one name or fragment, or queries for up to 20 searches in ONE tool step. For example: lookup_api({"queries":["getCell","getDistance","moveToward","useWeapon"]}). Do not put multiple names into a space-separated query string. To discover available names without reading all signatures, call lookup_api({"mode":"index","kind":"functions"}); follow its continuation if needed. The contracts already given above need not be looked up again. Group related missing signatures when preparation calls are scarce.
