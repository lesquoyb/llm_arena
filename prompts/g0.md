Write a LeekScript 4 strategy to win the tactical team fights described in this message.

Read the gameplay briefing and scenario first. They specify the team mode, roster,
final stats, equipment, turn limit and any build constraints. The briefing explains
which numeric IDs to use. In shared mode, write the script for the fixed roster.
In participant-team mode, choose and validate your team before testing or submitting.

Read corpus/index.md, corpus/rules.md, corpus/api-guide.md and authoring.md.
Use read_docs to inspect leekscript-v1/api.md and the equipment catalogs before
calling unfamiliar functions. All participants receive the same rules and tools.
You can compile, run training fights and inspect their replays with the tools.
The training opponent is passive, so a successful test does not prove a strong strategy.

Use your own .leek files only. Reads use offset and limit for pagination.
Finish with submit, using main.leek as the default entrypoint. If an optional
preparation limit is reached, the latest saved files are frozen, even if invalid.
Evaluation seeds and opposing scripts are unavailable during preparation.

Before submit, call analyze on the final saved version of your entrypoint and
configured team. Read diagnostic_messages: each error includes its file, line and
message. Fix every error and analyze again until status is valid. Recheck after
any further code edit or team entrypoint change. Compilation success does not
prove correct behavior: use test and read_replay to check execution when needed.
submit only freezes files and ends preparation; it does not validate or repair
your script. Invalid code is a failed strategy submission, even if the fight
process completes. You cannot fix that frozen version during evaluation fights.
